# Internationalization (i18n)

Family Roots uses [react-i18next](https://react.i18next.com/) with three supported locales:

| Locale | Flag | Notes |
|--------|------|-------|
| `en-GB` | 🇬🇧 | Default fallback; genealogical English house style |
| `es-ES` | 🇪🇸 | Hispanic genealogical vocabulary |
| `de-AT` | 🇦🇹 | Standard German kinship terms (Austrian locale tag) |

## Browser detection

On first visit, the app reads `navigator.languages` and maps tags through `resolveSupportedLocale()` in `src/i18n/locales.ts`:

- Any `en*` tag → `en-GB`
- Any `es*` tag → `es-ES`
- Any `de*` tag → `de-AT`
- Anything else → `en-GB`

Manual choice via the header language switcher is stored in `localStorage` under `roots-atlas-locale` and overrides detection on later visits.

Detection order: `localStorage` → `navigator`. Do not set a fixed `lng` in i18n init; use `fallbackLng: 'en-GB'`.

## Namespaces

JSON files live in `src/locales/{locale}/`:

| Namespace | Purpose |
|-----------|---------|
| `common` | Nav, auth, actions, counts, back links |
| `app` | Product name, home/login copy |
| `person` | Person form fields and profile |
| `tree` | Tree workspace, connect, backup, explain |
| `people` | People list filters and completeness |
| `health` | Data health issues and severity |
| `admin` | Family management and invites |
| `errors` | Domain error codes, Firebase auth, backup |

## Adding a string

1. Add the key to `src/locales/en-GB/{namespace}.json`.
2. Run `node scripts/sync-locales-from-en.mjs` (or translate manually in `es-ES` / `de-AT`).
3. Use `useTranslation` in the component:

```tsx
const { t } = useTranslation(['tree', 'common'])
return <span>{t('search.placeholder', { ns: 'tree' })}</span>
```

### Plural keys

Use i18next plural suffixes (`_one`, `_other`) in JSON, e.g. `counts.people_one` / `counts.people_other`, and call `t('counts.people', { count: n })`.

## Domain errors

Domain logic keeps stable **codes** (`DomainError.code`, `GraphIssue.code`, `ConnectionOption.reasonCode`). Presentation translates via `src/i18n/translate-domain.ts`:

- `translateDomainError(error, t)`
- `translateGraphIssueMessage(issue, t)`
- `translateConnectionReason(code, t)`
- `translateDuplicateReason(percent, birthClose, t)`

Do not match English message strings in UI code.

## Kinship labels

Locale-specific modules under `src/domain/kinship/` are selected by `getKinshipFormatter(locale)` in `kinship-labels.ts`. See [i18n-kinship-sources.md](./i18n-kinship-sources.md) for bibliographies and conventions.

## Tests

- `src/test/i18n.ts` — init i18n for unit/component tests
- `src/test/render-with-i18n.tsx` — render helper with `I18nextProvider`
- `scripts/check-i18n-keys.mjs` — asserts `es-ES` and `de-AT` have every `en-GB` key (runs in `npm run check`)
- E2E tests set `localStorage['roots-atlas-locale'] = 'en-GB'` in `beforeEach`

## Dates

`formatPartialDate` and `formatLifeSpan` in `src/lib/dates.ts` accept an optional locale. Spanish uses `/` as the date separator; English and German use `.`.
